# 命令历史与快捷命令

> 状态：Accepted
>
> 数据模型决策见 [ADR-0008](../20-architecture/adr/0008-pinned-history-as-snippets.md)：**快捷命令 = 置顶的历史，不是独立实体。**

## 核心心智模型

只有一个概念：**命令记录**。它有一个 `pinned` 标记。

```
一个列表，两个视图：
  ┌─ 置顶区（pinned，按 pin_order） ── 就是「快捷命令」
  └─ 历史区（其余，按时间倒序）
搜索时同时搜两者。
```

用户永远不需要"创建快捷命令"这个动作。他只是给一条已经存在的历史打了个星。

## 点击行为（AC-6.4）

| 操作 | 行为 |
|---|---|
| 点击（任意端） | **填入 Composer**，光标置于末尾，**不执行** |
| `Shift+点击`（桌面） | 直接执行 |
| 长按（移动端） | 直接执行 |
| 点击 ☆ | 切换 `pinned` |

**默认不执行**是刻意的：

- 从历史里选一条命令，通常是因为它"差不多对" —— 需要改个分支名、改个容器名、改个路径
- 直接执行有误操作风险（历史里可能有 `rm -rf`）
- 想直接执行时多按一个 Shift / 长按 0.5 秒，成本极低

这也是**取消参数化模板的前提**：填入 + 编辑已经完整覆盖了模板参数的场景。

## 命令面板（AC-6.8）

`Ctrl/Cmd+K`。**桌面端的唯一主入口** —— 一个入口搞定所有事，因此不需要一堆快捷键。

```
┌──────────────────────────────────────────────┐
│ > go te                                      │
├──────────────────────────────────────────────┤
│ ★ go test ./...                    ~/webterm │  ← 快捷命令优先
│   go test -run TestRing ./internal/ringbuf   │
│   go test -v ./internal/oscparse    exit 1   │
│ ─────────────────────────────────────────────│
│ ⧉ 会话：go-test-runner                       │  ← 会话
│ ─────────────────────────────────────────────│
│ ⚙ 新建会话                                   │  ← 动作
└──────────────────────────────────────────────┘
```

搜索范围与排序：

1. **快捷命令**（`pinned`）—— 始终优先
2. **历史命令** —— 按"模糊匹配得分 × 时间衰减"排序。同一命令文本只出现一次（取最近一次执行）
3. **会话** —— 名字/CWD 匹配
4. **动作** —— 新建会话、切换主题、打开设置等

匹配算法：子序列模糊匹配（连续匹配加权、词首匹配加权），不用正则。

行为：`Enter` 执行默认动作（命令 → 填入 Composer；会话 → 切换；动作 → 执行）；`Shift+Enter` 对命令 = 直接执行。

## 历史面板

从侧栏/菜单打开的完整列表（命令面板是快速入口，历史面板是浏览与管理入口）。

```
┌────────────────────────────────────────────────────────┐
│ 🔍 搜索命令…                     [仅当前目录] [仅失败] │
├────────────────────────────────────────────────────────┤
│ 快捷命令                                                │
│ ★ 重启服务      systemctl --user restart api        ⋮  │
│ ★ go test ./...                                     ⋮  │
├────────────────────────────────────────────────────────┤
│ 今天                                                    │
│ ☆ go build -o bin/webterm ./cmd/webterm   0   1.2s  ⋮  │
│ ☆ go test ./internal/ringbuf              1   0.4s  ⋮  │
│   ~/github/webterm                              12:03  │
│ ☆ git push origin feat/30-protocol-core   0   2.1s  ⋮  │
├────────────────────────────────────────────────────────┤
│ 昨天 …                                                  │
└────────────────────────────────────────────────────────┘
```

每条显示：命令原文、退出码、耗时、CWD、时间。按天分组。

- **退出码**：0 用弱色（不干扰），非零用警示色。这让"昨天那条失败的命令"极易定位
- **未完成的命令**（`exit_code IS NULL`，shell 在命令结束前死了）显示 `—`
- 过滤器：`仅当前目录`（按当前会话的 CWD）、`仅失败`（`exit_code != 0`）
- `⋮` 菜单：置顶/取消置顶、设置短名、复制、删除

### 搜索（AC-6.3）

- 按命令原文子串（不区分大小写）
- 可叠加 CWD 过滤
- 结果按时间倒序、分页（每页 100，滚动加载）
- v0.1 用 `LIKE`，不用 FTS5（[ADR-0005](../20-architecture/adr/0005-sqlite-pure-go.md)）

## 快捷命令的管理（AC-6.6）

### 短名（`label`）

置顶后可以设置一个短名，比如给 `systemctl --user restart api` 起名 `重启服务`。

- 有 `label` 时按钮/列表显示 label，命令原文作为副标题（或 tooltip）
- 没有 `label` 时显示命令原文，超长则中间省略（保留开头和结尾 —— `docker logs -f …-web-1` 比 `docker logs -f cont…` 有用）

移动端的快捷按钮条空间极小，`label` 在那里价值最大。

### 排序

- 拖动排序（桌面拖列表项，移动端长按后拖）
- 改动立即持久化（批量 `PATCH /api/commands`，一次提交所有受影响的项，避免中间态出现重复的 `pin_order`）

### 手动新建（次要入口）

在快捷命令区的 `+` 按钮，输入一条从没执行过的命令。

实现上是往 `commands` 插一行 `exit_code = NULL, duration_ms = NULL, pinned = 1`。语义上稍微别扭（它不是"历史"），但换来了整体的简化。这类记录可用 `exit_code IS NULL AND duration_ms IS NULL AND pinned = 1` 识别。

放在次要位置，因为主路径是从历史置顶。

## 移动端快捷命令条（AC-6.7）

Composer 上方一行，40px 高，横向滚动。

```
[重启服务] [go test ./...] [docker ps] [tail -f log] →
```

- 内容 = `pinned` 列表按 `pin_order`
- 点击 = 填入 Composer；长按 = 直接执行（长按 500ms，带触觉反馈如果可用）
- 长按拖动 = 排序
- 为空时整条隐藏（不占空间，也不显示"暂无快捷命令"这种废话）
- `short` 布局（手机横屏）下隐藏，从 sheet 访问

## 历史导航（Composer 里的 `↑`）

见 [`input-modes.md`](input-modes.md#历史导航)。要点：数据源是 agent 的 `commands` 表，**不是 localStorage** —— 所以手机上按 `↑` 能翻到笔记本上敲过的命令。这是把历史放服务端的直接收益。

## 删除与清空（AC-6.9）

- 单条删除：`⋮` 菜单，直接删（有 3 秒撤销 toast）
- 清空全部：设置页里，**二次确认**（输入 `DELETE` 或勾选确认框）
- 清空时**保留置顶记录**并明确告知：`将删除 12043 条历史，保留 8 条快捷命令`

## 隐私（AC-6.2 / US-6.7）

以空格开头的命令不产生记录，由 shell 集成侧实现（[`../30-protocol/shell-integration.md`](../30-protocol/shell-integration.md#41-命令原文的获取)）。

**UI 上必须让用户知道这件事** —— 否则这个功能等于不存在。设置页与首次使用引导里说明：

> 以空格开头的命令不会被记录。贴 token / 密码时在前面加个空格。

## 淘汰策略（AC-6.10）

历史超过上限（默认 50000 条）时，按 `started_at` 淘汰最旧的**非置顶**记录。置顶记录永不淘汰。

这是 [ADR-0008](../20-architecture/adr/0008-pinned-history-as-snippets.md) 的直接后果：快捷命令的生命周期跟历史绑定，所以淘汰逻辑必须保护它们。
