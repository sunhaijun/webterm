# 历史隐私

> 状态：Accepted

命令历史是 webterm 最有用的功能之一，也是最容易变成隐患的。这篇定义边界。

## 铁律：终端输出不落盘

**环形缓冲纯内存。任何情况下终端输出都不写入磁盘。**

为什么：终端输出里有

- `cat .env`、`env`、`kubectl get secret -o yaml` 的结果
- 日志里的 token、session id、连接字符串
- `git push` 时打印的 URL（可能含 token）
- AI agent 的对话内容

这些东西一旦落盘就成了长期的泄露面。所以选择：**要么在内存里，要么不存在。**

对应不变式（[CLAUDE.md](../../CLAUDE.md)）：`3. 输出不落盘`。
验证：`IT-privacy-1` 跑一个会话输出特征字符串 `WEBTERM_CANARY_<随机>`，然后 grep 整个数据目录 + 日志，断言零命中。

### 后果

- **agent 重启后看不到之前的输出**。这是 [ADR-0003](../20-architecture/adr/0003-no-tmux.md) 会话不持久化的必然结果，两件事互相印证。
- 没有"会话录像"功能。如果将来要做，必须是显式开关 + 明确的界面告知 + 独立的文件权限，且默认关闭。

### 浏览器本地的一份快照（ADR-0024）

"输出不落盘"约束的是 **agent 侧**。[ADR-0024](../20-architecture/adr/0024-scrollback-layered-model.md) §3 让**浏览器**在刷新前把当前终端缓冲（最多 2000 行）存进 IndexedDB，刷新后写回去 —— 否则刷新就只剩最后一屏。这份数据：

- 只在**用户自己的浏览器**里，同源隔离，不回传 agent、不进任何日志；
- 每会话一条，最多留活动会话 + 最近 3 个，超过 24 小时即丢弃；
- **配对失效或设备被吊销时必须一并清除**（与会话 Cookie 同时失效，AC-5.14）；
- 备用屏会话不存 —— 那是屏幕状态不是输出流，存了也没意义。

它不动摇上面那条铁律：agent 的磁盘上仍然一个字节的终端输出都没有。但"浏览器本地留了一份"必须写在这里，不能让用户自己发现。

## 落盘的是什么

只有命令**元数据**：

| 字段 | 敏感度 | 说明 |
|---|---|---|
| `text`（命令原文） | **中** | 用户主动输入的。可能误含凭据 → 见下面的空格规则 |
| `cwd` | 低 | 泄露目录结构 |
| `exit_code` | 无 | |
| `started_at` / `duration_ms` | 低 | 泄露工作时间模式 |
| `session_name` | 低 | 通常就是目录名 |

命令原文是唯一需要认真对待的。

## 空格前缀规则（AC-6.2 / US-6.7）

**以空格开头的命令不产生记录。**

```bash
$  export GITHUB_TOKEN=ghp_xxxx     # 前面有空格 → 不记录
$ export GITHUB_TOKEN=ghp_xxxx      # 会被记录
```

### 为什么用这个约定

它是 bash 用户已经熟悉的习惯（`HISTCONTROL=ignorespace`）。复用现有肌肉记忆比发明新机制好。

### 实现

在 shell 集成侧（[`../30-protocol/shell-integration.md`](../30-protocol/shell-integration.md#41-命令原文的获取)）。

集成脚本用 `history 1` 取命令原文。`HISTCONTROL=ignorespace` 生效时，以空格开头的命令**不进 bash 历史**，于是 `history 1` 返回的是上一条命令 —— 脚本检测到"这次和上次一样"就跳过上报。

**副作用即是特性**：不需要额外的过滤逻辑，bash 自己的机制就实现了它。

集成脚本必须确保 `HISTCONTROL` 包含 `ignorespace`（如果用户没设则追加，不移除用户已有的设置）。

### 局限（必须让用户知道）

- 命令写在**一行的中间**（`foo && export TOKEN=x`）时无效
- 通过 heredoc、`read`、交互式 prompt 输入的凭据不受此规则保护（但它们本来也不在命令行里，不会被记录）
- **用户不知道这个规则的话，它等于不存在**

所以 UI 上必须说明（见 [`../40-frontend/commands-ux.md`](../40-frontend/commands-ux.md#隐私ac-62--us-67)）：设置页 + 首次使用引导里明确写：

> 以空格开头的命令不会被记录。贴 token / 密码时在前面加个空格。

## 用户的控制手段（AC-6.9）

| 手段 | 位置 |
|---|---|
| 删除单条历史 | 历史面板 `⋮` 菜单（带 3 秒撤销） |
| 清空全部历史 | 设置页，二次确认，明确告知保留 N 条快捷命令 |
| 完全关闭历史记录 | 设置项 `--no-history` / UI 开关。关闭后不写 `commands` 表，但输入模式自动切换仍工作（那依赖 OSC 133，不依赖命令原文） |

**"完全关闭"这个开关很重要** —— 它让用户在做敏感工作时可以一键静默，而不是事后清理。

## 日志（AC-8.5）

agent 的日志**不得包含**：

- 配对码（任何形式，包括前缀）
- 会话 Cookie token
- 命令原文
- 终端输出

**可以包含**（刻意保留）：

- IP 与 User-Agent —— 设备列表和限速需要
- 会话 sid、字节计数、seq —— 排障必需
- 错误码与堆栈

日志级别默认 `info`。`--log-level debug` 会输出更多协议细节，但**仍然不输出上面禁止的内容** —— debug 模式不是安全旁路。

OSC 解析失败时记 debug 日志，但**只记序列类型和长度，不记负载内容**（负载可能是命令原文）。

## 数据目录权限

```
$XDG_DATA_HOME/webterm/    0700
├── webterm.db             0600
├── certs/                 0700
└── run/                   0700   （rcfile 0600）
```

同机的其它本地用户不在信任边界内（[`threat-model.md`](threat-model.md#信任边界)）。

**rcfile 不放 `/tmp`**：`/tmp` 是所有用户可读的目录，且系统清理策略可能在会话运行期间删掉文件。

## 备份的责任在用户

webterm 不做自动备份。`webterm.db` 是单文件，用户可以自己 `cp`（建议先 `sqlite3 webterm.db ".backup"` 或停服，避免 WAL 状态不一致）。

**必须在文档里提醒**：这个文件包含完整的命令历史，备份到哪里就等于把历史复制到哪里（[`../80-ops/install.md`](../80-ops/install.md)）。

## 未来（不在 v0.1）

- **敏感命令模式匹配**：自动识别 `export *TOKEN*=`、`curl -H "Authorization: ...`" 之类的模式并拒绝记录。听起来好，但正则永远不全，且会给用户虚假的安全感 —— 反而不如"空格前缀"这个用户主动、可预测的机制。**倾向于不做。**
- **历史加密**：用一个从配对码派生的密钥加密 `commands.text`。收益有限（agent 运行时必须能解密，所以密钥必须在内存里），复杂度高。倾向于不做。
