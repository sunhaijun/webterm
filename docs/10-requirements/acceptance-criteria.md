# Acceptance criteria

> Status: Accepted

Every criterion must be **automatically verifiable** and implemented in [`../70-testing/e2e-scenarios.md`](../70-testing/e2e-scenarios.md) or a Go test.
The **Verified by** column: `UT-*` = Go/Vitest unit test, `IT-*` = Go integration test, `E2E-*` = Playwright.

An item with no way to verify it doesn't belong here.

## AC-1 Deployment and authentication (US-1)

| ID | Criterion | Verified by |
|---|---|---|
| AC-1.1 | `webterm serve --domain X`, with 80/443 reachable and DNS correct, obtains a certificate automatically and serves HTTPS (port 443 by default, change with `--https-port`); at startup it warms up the certificate once so the renewal timer is armed regardless of traffic; renews `min(30 days, lifetime/3)` before expiry. Renewal needs only one of 80 or 443 reachable from the internet (HTTP-01 on 80, TLS-ALPN-01 on 443) | IT-tls-1 (local fake ACME CA, see [strategy.md, "Why not pebble"](../70-testing/strategy.md#why-not-pebble)) |
| AC-1.2 | `webterm serve --dev` serves on `http://127.0.0.1:8080` without requesting a certificate | IT-tls-2 |
| AC-1.3 | On first start with no authorized devices, if stdout is a terminal it prints the pairing URL and an ASCII QR code; otherwise (systemd: the journal) only a hint to run `webterm pair`, never the code (AC-8.5, ADR-0047 §3) | IT-pair-1 |
| AC-1.4 | Pairing code: single use, void once used; expires after 5 minutes; the URL code has 32 bytes of entropy; constant-time comparison. The same pairing also issues a 16-digit decimal code (ADR-0017); both keys are stored hashed in the same row, **using either one voids the row**, and the same TTL and comparison rules apply | UT-pair-1..5 |
| AC-1.5 | The pairing code travels in the URL **fragment**; it never appears in the server's access logs | IT-pair-2 |
| AC-1.6 | After 5 failed pairings per minute per IP, back off; return 429 during the backoff | IT-pair-3 |
| AC-1.7 | Every route except `/pair`, static assets and `/healthz` returns 401 without a valid cookie, **including the WebSocket upgrade** | IT-auth-1 |
| AC-1.8 | The WebSocket upgrade and state-changing `/api` requests check that `Origin` matches the service domain; a mismatch returns 403. The domain is compared lowercase | IT-auth-2, UT-domain-case |
| AC-1.9 | The session cookie is `HttpOnly; Secure; SameSite=Strict; Path=/`; `Secure` may be omitted under `--dev` | IT-auth-3 |
| AC-1.10 | The DB stores a hash of the cookie token, not the token itself | UT-auth-1 |
| AC-1.11 | After a device is revoked, its next request (including an already established WebSocket) is cut off within 5 seconds and must re-pair. The pairing page it lands on says it was revoked — also when the page is opened later: a request carrying a revoked device's cookie gets `401` with `code: "revoked"` (and the cookie cleared) instead of the plain "pairing required" | IT-auth-4, E2E-15 |
| AC-1.12 | The DB file mode is `0600` | IT-store-1 |
| AC-1.13 | When certificate issuance fails, stdout gives the cause and the fix (covering at least: port 80 in use, DNS not pointing at this machine, ACME rate limit), not a raw Go error; `webterm doctor` checks the same prerequisites one by one (US-7.2) | IT-tls-3 |
| AC-1.15 | Manual pairing (ADR-0017): the terminal prints the digit code as `dddd-dddd-dddd-dddd`; `GET /pair` without a fragment shows a numeric input (`inputmode=numeric`, grouped in fours as you type, submittable only at 16 digits) that accepts spaces and `-`; submission uses the same `POST /auth/pair`, and the server strips separators before matching the digit code; wrong / expired → 401 message, input kept for another try | IT-pair-4, E2E-27 |
| AC-1.14 | PWA: `manifest.json` is complete, the Service Worker registers, `display: standalone`; the SW **caches only the static shell**, never `/api/*` or `/ws`; offline shows a clear status in the connection banner and keeps retrying (US-1.4, ADR-0049) | E2E-17 |
| AC-1.16 | IP mode (ADR-0044): when `--domain` is an IPv4 literal, request a certificate for an IP identifier (RFC 8738) with the `shortlived` profile, HTTP-01 only; the handshake ignores SNI and always serves this certificate, and **a handshake never triggers issuance**; the certificate is cached in `certs/<ip>` (same format as autocert) and a restart reads the cache without contacting the CA; renew when less than 1/3 of the lifetime remains, retry hourly on failure; a CA directory without `shortlived` → readable error; an IPv6 literal → rejected with an explanation | IT-tls-4..6, UT-ipcert-1..3 |
| AC-1.17 | No staging (ADR-0044 §3): `serve` doesn't accept `--acme-staging`; `acme-staging` in the config file → startup fails, saying the option was removed and the line can simply be deleted | UT-config-removed-key |
| AC-1.18 | `webterm doctor --acme`: once the static checks pass, it temporarily listens on the http/https ports, requests a production certificate and stores it in `certs/` (the service uses it on start without issuing a second one; if a valid certificate already exists, it uses that and reports that the CA wasn't contacted); on failure it gives the same cause-and-fix as startup. In IP mode doctor skips DNS and checks "this machine's public IP == `--domain`" instead | IT-doctor-acme-1..2, UT-doctor-ip |
| AC-1.19 | `webterm install` (ADR-0045): runs the install.sh embedded in the binary, with itself as `--binary`; an install.sh fetched from the web downloads and verifies the binary, then hands over to that binary's `install`, rejecting old versions that don't have `install`; without `--domain`, reuse `install-state`, falling back to the public IPv4; `domain` / ports in the config file are synced on every install; a first install runs `doctor --acme` and opens enabled ufw/firewalld before starting the service, then runs `pair --wait` after start to print the pairing code | UT-install-embed, UT-install-handover, UT-install-default-addr, UT-install-config-sync, UT-pair-wait, manual checklist "Deployment" |
| AC-1.20 | In the status overview, the certificate's "expiring soon" yellow threshold is `min(10 days, lifetime/4)`: a 90-day certificate still turns yellow at 10 days, and a freshly issued 6-day IP certificate is not yellow | UT-status-cert |
| AC-1.21 | Guided install (ADR-0046), with a terminal: a fresh install first states the one external step (cloud firewall); with no `--domain` and no previous install it asks for the address (Enter = detected public IPv4, a pasted URL is trimmed); `doctor --guide` shows the exact `A` record and polls until the domain resolves here; when the CA can't reach the server it names the provider's console page (from DMI), waits for Enter, re-checks with Let's Encrypt staging in a throwaway directory, and only then requests the production certificate. Without a terminal nothing prompts: one check, same explanation, non-zero exit | UT-doctor-guide-1..4, UT-issue-unreachable, manual checklist "Deploy" |
| AC-1.22 | **Sign out this device** ([ADR-0048](../20-architecture/adr/0048-sign-out.md)): Settings has a "Sign out this device" button that asks for confirmation in an in-app sheet. Confirming sends `POST /auth/logout` (authenticated, `Origin` checked): the agent revokes this device, clears the cookie and sends `Clear-Site-Data`; the page also removes its `webterm.*` `localStorage` keys, its service worker and its caches, then shows the pairing page with "Signed out". Afterwards the old cookie gets `401` on `/api/*` and `/ws`, and the device's other tabs are cut off within 5 seconds. Offline, it doesn't sign out and says so; a `401` reply counts as signed out | IT-auth-5, UT-signout-1, E2E-46 |
| AC-1.23 | **Attach over SSH** ([ADR-0050](../20-architecture/adr/0050-ssh-attach.md)): the agent creates `<data-dir>/run/attach.sock` (`0600`) on start and removes it on exit; it speaks the WebSocket protocol, and a peer with another uid gets `403`. `webterm attach`, run through `ssh -t`: no sessions → creates one and attaches; one → attaches; several → a numbered list in display order and a prompt. A number picks by position (the tab bar's `[n]`); anything else is a name: an exact match first, then a case-insensitive substring; several matches → the list narrowed to them; none → an error followed by the list, exit status 1. `--new` creates a session and attaches; `--list` prints `N  name  cwd` (`exited` appended for exited sessions) and needs no terminal; any other use without a terminal exits 1 with a message naming `ssh -t`. While attached: the local screen is the session's screen (the client's output fed to a fresh emulator renders the same screen as the agent's emulator, also after a column change); keystrokes reach the session; the browser sees and can use the same session at the same time; closing ssh (`SIGHUP`) leaves the session running. On exit the terminal settings are restored and the modes listed in ADR-0050 §3 are turned off. A dropped socket connection reconnects (within 30 seconds), and input typed meanwhile arrives exactly once. When the session's shell exits, `[Exited (code N) · Enter to close]` appears; `Enter` closes the session, any other key leaves it. Attaching to the session the command runs in is refused | IT-attach-1..7, UT-attach-pick, E2E-47 |
| AC-1.24 | **`webterm setup`** ([ADR-0055](../20-architecture/adr/0055-webterm-setup.md)): reports each item as ok / add / left as is / skipped — claude (`"preferredNotifChannel": "terminal_bell"` in `~/.claude/settings.json`, only if `~/.claude` exists; any value but `auto` is left as is), codex (`notifications = true`, `notification_condition = "always"` under `[tui]` in `~/.codex/config.toml`, only if `~/.codex` exists; only missing keys are added, and `notifications = false` is left as is); nothing in the shell's files ([ADR-0058](../20-architecture/adr/0058-enter-key-and-two-row-strip.md) §4). `--check` changes nothing and exits 1 when something would be added, 0 otherwise; `--yes` adds without asking; without either it asks once on the terminal and, with no terminal, adds nothing. A second run changes nothing. Changes insert lines only (other bytes, order and comments kept), back each file up to `<file>.webterm-bak` first, keep its mode, write a symlinked file through to its target, and leave a file that doesn't parse untouched | UT-setup-claude, UT-setup-codex, IT-setup-1 |
| AC-1.25 | **The installer offers it** ([ADR-0055](../20-architecture/adr/0055-webterm-setup.md) §3): a first install asks on the terminal whether to set up claude and codex and runs `webterm setup --yes` on yes; `--setup` runs it without asking on any install, `--no-setup` skips the question; with no terminal and no `--setup` it's skipped with a hint; neither flag is written to install-state, so `webterm update` never runs it; `--dry-run` only says it would run `webterm setup --yes` | UT-install-setup |

## AC-2 Resume (US-2) ★ core

| ID | Criterion | Verified by |
|---|---|---|
| AC-2.1 | **Byte-level continuity**: run the same output script twice, forcing a disconnect and reconnect midway through the second run; at the end, the serialized xterm buffers of the two runs are **byte-for-byte identical** | E2E-2 ★ |
| AC-2.2 | Sessions don't pause while disconnected: the PTY keeps running and the ring buffer keeps filling | IT-resume-1 |
| AC-2.3 | On reconnect / switch-back the client reports `out_seq`; when `out_seq > 0` and still inside the ring buffer window, take the **incremental** path: the agent sends only the raw bytes after `out_seq` and never resends bytes already received | UT-ring-1, IT-resume-2 |
| AC-2.4 | Input submitted while disconnected is written to the PTY after reconnecting, in order, with no duplicates and no loss — **including input typed into a session the user then switched away from**, which goes out right after the reconnect, not when the user switches back. An abandoned connection that ends later on the agent doesn't discard what the new one queued. Up to 256 KiB can be pending; more is refused with a message, and the text page keeps its draft and sends no Enter | E2E-3, IT-resume-3, UT-reconnect-2, IT-stale-detach, UT-input-size-1 |
| AC-2.5 | `out_seq` equals exactly the session's cumulative PTY output bytes: the agent doesn't rewrite the output stream; `SNAPSHOT` frames don't count toward `out_seq` | UT-seq-1 |
| AC-2.6 | **Snapshot path** ([ADR-0026](../20-architecture/adr/0026-agent-holds-terminal-state.md)): when `out_seq == 0` (first open, reload), the client has fallen out of the ring buffer window, or the column count changed on subscribe, the agent sends `SNAPSHOT` (`seq` = `head_seq` at generation time, content = current screen + up to 2000 lines of history + modes), then OUTPUT from `seq`; the client `reset`s, writes the snapshot and sets `out_seq = seq`. **Both reconnect (`welcome.resumed[].status == "snapshot"`) and switch-back (`subscribe`) meet this**; when one snapshot spans several frames, all but the last carry `MORE` and the client applies it only once complete; never show "history truncated" | E2E-4, E2E-30, IT-sub-2, IT-snapshot-1 |
| AC-2.8 | Heartbeat: the client sends a protocol-level ping every 30 seconds and declares the connection dead (and reconnects) if no `pong` arrives within 10 seconds; the agent closes the connection after 60 seconds without any frame | UT-hb-1, IT-hb-1 |
| AC-2.9 | The client reconnects with exponential backoff (starting at 0.5s, capped at 15s, with jitter); a network-online event triggers an immediate retry | UT-reconnect-1 |
| AC-2.20 | **Zombie connections are exposed immediately** (ADR-0020): on the `online` event / page becoming visible, send a `ping` even if the client believes it's online; no `pong` within **2 seconds** → close and reconnect. When the line is dead without an `onclose` (screen off, network switch, NAT eviction), the time from "user returns to the foreground" to the status bar showing "reconnecting" is **at most 5 seconds** (previously up to 40 seconds, during which every keystroke went into a dead socket with no indication). Giving up on the socket doesn't wait for `onclose`, which a dead link may not fire for a minute; a reconnect already in progress is replaced, never doubled (ADR-0047 §2) | UT-hb-2, UT-hb-3, UT-reconnect-3, E2E-33 |
| AC-2.21 | **Snapshot screen-level consistency** ([ADR-0026](../20-architecture/adr/0026-agent-holds-terminal-state.md) §10): take recorded bytes from real programs, cut them at any point k (including inside escape sequences and multi-byte characters) and generate a snapshot there; xterm fed the snapshot and then the bytes after k ends up cell-for-cell identical to xterm fed all the bytes directly (characters, widths, colors, attributes, cursor, modes); only the three known differences listed in ADR-0026 and soft-wrap markers may differ | UT-vterm-golden, UT-snapshot-xterm |
| AC-2.22 | **A column change resends the snapshot**: when `resize` or `subscribe` brings a column count different from the session's, the agent, under the lock, resizes the emulator, generates a snapshot and sends it to every subscriber of the session; `TIOCSWINSZ` happens outside the lock, so whatever the program redraws on SIGWINCH comes after the snapshot; a row-only change sends no snapshot | IT-resize-2, E2E-42 |
| AC-2.23 | **Split UTF-8 loses no characters**: the client decodes bytes into strings with a per-session streaming UTF-8 decoder before writing to xterm; when a multi-byte character is split across two OUTPUT frames (including `。` `…` `—`, whose second byte is `0x80`), the character still appears in the terminal; a snapshot gets a fresh decoder | UT-decode-1, E2E-43 |
| AC-2.10 | The connection state is clearly shown, **always in one place: the banner at the top of the terminal** ([ADR-0049](../20-architecture/adr/0049-connection-status-in-one-place.md)). Connecting / reconnecting (with a countdown to the next retry) show while not online; for 3 seconds the banner also carries a note: "Resumed · caught up N KB" after a reconnect, "Session ended" after an agent restart, or an action refused while offline. From the first frame of a page load the banner is already in its final position (the gate draws a skeleton of the app with it), and an agent unreachable at startup shows "Can't reach the agent · retrying" there. On `wide`, a status dot also sits permanently at the right of the tab bar. The banner **overlays the terminal**: the terminal's rows and columns don't change as it appears or disappears, and no `resize` is sent. The status text (`conn-text`) is always in the DOM — only visually hidden while online — so `aria-live` keeps announcing; the note is `conn-note`. Toasts carry only messages unrelated to the connection | E2E-5, UT-connbanner-1 |
| AC-2.11 | Unsubscribed sessions keep buffering and feeding the emulator on the agent; switching back takes the incremental or snapshot path per AC-2.3 / AC-2.6, without losing the screen | E2E-6, IT-sub-1, E2E-31 |
| AC-2.12 | `in_ack` is tracked per `(client_id, sid)` and **survives reconnects**: after reconnecting, the client resends from `welcome.resumed[].in_ack` without triggering `input_gap` | IT-resume-3 |
| AC-2.13 | If `hello.instance_id` differs from the agent's current value, every `resume` entry is `gone` (so a sid reused after an agent restart isn't mistaken for the old session) | IT-resume-4 |
| AC-2.14 | **A hot upgrade keeps sessions** (ADR-0016): on `SIGUSR2` / `reexec` the agent execs the new binary in place, keeping its PID; every session's shell keeps running, `instance_id` is unchanged, and ring buffers, **emulator state** and `in_ack` are handed over intact; **a snapshot of the same session is byte-identical before and after the handoff**; incremental resume across the handoff meets the same bar as AC-2.1, and input not yet written is neither lost nor duplicated; if the preflight fails, abort and keep serving — **never fall back to a restart**. The new process starts with the command line `reload -- serve …` gives it (install.sh passes the unit's, so a new address or port applies), and the preflight rejects a command line or config file the new binary can't start with; a takeover that turns out to be a restart is reported as lost sessions; close, rename and move wait for the handoff (ADR-0047 §1, §4) | IT-handoff-1, UT-vterm-handoff, E2E-26, UT-reload-args, IT-handoff-wait |
| AC-2.15 | **Replay must not echo**: bytes written from a `SNAPSHOT` and incremental catch-up bytes (before the client's `catchup_to`) are marked as replay; during replay, the terminal's automatic replies to historical queries (DSR / DA / `CSI ?u` …) **must not be written to the PTY**, while user input passes as usual. On subscribe, **the size goes in the `subscribe` message**, not in a separate `resize` | E2E-30, E2E-31, E2E-34, UT-replay-1, UT-replay-2 |
| AC-2.24 | **The agent isn't OOM-killed before its sessions** (ADR-0034): `install.sh` installs a system service that runs as the installing user; the agent process has `oom_score_adj = -900` and `OOMPolicy=continue`; session shells are at 0 from the first line of user code (processes started while the login shell reads its profile are also at 0), and the agent goes back to its own value after starting the shell; when a process in a session is OOM-killed, the unit keeps running and other sessions are unaffected; machines still on a user service hot-upgrade by default without migrating, migrate only with `--force-restart`, and refuse to migrate when run inside a webterm session | UT-oom-1, IT-oom-1, UT-install-unit, manual checklist "Deployment" |

## AC-3 Input (US-3)

| ID | Criterion | Verified by |
|---|---|---|
| AC-3.3 | In direct input, nothing is written to the PTY during composition; on `compositionend` the final text is written at once. **Composition state must have a fallback reset** (ADR-0020): `blur`, and a capture-phase `keydown` with `isComposing === false`, both reset `composing` to false immediately — when switching IMEs or windows `compositionend` may never arrive, and without the fallback the session's terminal input breaks **permanently** until the page is reloaded | UT-input-2, UT-raw-2, E2E-34 |
| AC-3.17 | **The input path is observable** ([ADR-0020](../20-architecture/adr/0020-input-never-silently-dropped.md), corollary 3): `__webterm.inputStats()` reports counts and **the time of the most recent event** for four stages — key reaches the page (**capture-phase** `keydown`) → focus is in the terminal → xterm emits `onData` → sent to the agent (INPUT frame) — plus the number dropped by the replay gate, unacked bytes and the currently focused element, and a `verdict` (which stage is broken); **present in production builds too** | UT-inputstats-1..2, E2E-34 ④ |
| AC-3.14 | In direct input, **characters the on-screen keyboard inserts directly** (such as full-width punctuation from the iOS Chinese keyboard) must reach the PTY: the frontend sends non-composition `beforeinput` / `insertText` itself and calls `preventDefault`, instead of relying on xterm's keydown/input heuristics; the composition path is unaffected and the same text isn't sent twice. **Deduplication suppresses only the one copy already sent by another path, and only once** (the resend from `compositionend`, a character `keypress` already sent); **typing the same character twice must send it twice** — deduplicating by content + time window silently eats the second one ([ADR-0020](../20-architecture/adr/0020-input-never-silently-dropped.md)) | UT-raw-1, E2E-7 |
| AC-3.4 | `Ctrl+C` / `Ctrl+D` / arrow keys / `Esc` / function keys from direct input and from the extra keys map to the correct control bytes, with the extra keys using the same encoding as a physical keyboard; arrows and `Home` / `End` follow application cursor mode (with DECCKM on, send `ESC O A` / `ESC O H`), read at key time, not cached | UT-keymap-1 |
| AC-3.8 | When the on-screen keyboard opens (`visualViewport` resize), the terminal area shrinks instead of being covered, the extra keys sit fully visible right above the keyboard, and nothing jumps; the form doesn't change | E2E-21 |
| AC-3.10 | The text page `textarea` disables `autocorrect` / `autocapitalize` / `spellcheck`, judged by the actual DOM attribute value (`autocorrect="off"`, not the `on` a framework may reflect it as) | UT-input-3, E2E-40 |
| AC-3.11 | When the terminal size changes, send `resize` to the agent, which applies `TIOCSWINSZ` to the PTY; resize messages are debounced by 100ms. Rows/columns = available size ÷ a **stable** cell size (independent of the current rows/columns, [ADR-0033](../20-architecture/adr/0033-own-fit.md)): measuring repeatedly with the container size unchanged yields the same rows/columns; changing only the height keeps the column count | IT-resize-1, UT-resize-1, UT-fit-1, E2E-42 |
| AC-3.18 | **Extra keys** ([ADR-0025](../20-architecture/adr/0025-termux-style-ui.md) §2): always shown on `compact`, shown on `wide` when `pointer: coarse`; two rows, 15 keys, in order `ESC / - HOME ↑ END PGUP` and `TAB CTRL ALT ← ↓ → PGDN ↵`, **independent of the foreground program and the prompt state**, with ⌘ at the end of the first row while claude or codex runs (AC-3.24, [ADR-0058](../20-architecture/adr/0058-enter-key-and-two-row-strip.md)); all visible at 393px width without horizontal scrolling; keys call `preventDefault` on `pointerdown`, and `document.activeElement` is the same before and after a press; **a control acts only when released within 10px of where it was pressed** (the pressed look `data-pressed` goes once the finger moves past 10px; a drag sends nothing, [ADR-0056](../20-architecture/adr/0056-collapsible-extra-keys.md) §1); bytes go out through `onData` (counted in `inputStats`); a tap on CTRL / ALT applies to the next key only (including the next character typed on the on-screen keyboard), a long press locks it, another tap unlocks; active and locked states have `data-sticky` and a highlight | UT-keys-1, E2E-10 |
| AC-3.19 | **Text page**: switch with ✎, or swipe up on the keys page / down on the text page while its box is scrolled to the top ([ADR-0056](../20-architecture/adr/0056-collapsible-extra-keys.md)); a sideways swipe doesn't switch; the terminal's rows and columns don't change and no `resize` is sent. Enter: ignored while composing; with content → the content goes through `term.paste()` (wrapped if the program enabled bracketed paste, newlines converted to `CR`), **immediately followed by `\r`**, then the box is cleared; empty → send `\r`; Enter never inserts a newline in the box; everything goes through `onData` (counted in `inputStats`); after sending, stay on the text page with focus unchanged ([ADR-0027](../20-architecture/adr/0027-text-page-enter-submits.md)); the text box has borders on all four sides and fits entirely inside the extra-keys slot | UT-textinput-1, E2E-40 |
| AC-3.20 | **Tapping the terminal**: if the foreground program has enabled mouse tracking, the tap goes to xterm to report; otherwise it toggles the on-screen keyboard (blur if the terminal has focus, focus if not), and the focus happens inside this touch's event handler; a movement of ≥ 10px is a drag, not a tap | E2E-10 |
| AC-3.21 | **Vertical touch drag** ([ADR-0029](../20-architecture/adr/0029-touch-drag-to-wheel.md), [ADR-0032](../20-architecture/adr/0032-drag-wheel-per-row.md)): if the foreground program has enabled mouse tracking, a drag that has moved 10px and is mostly vertical becomes wheel events: **one per row height of finger movement** (accumulated from the start point, with the remainder carried to the next frame), sent as soon as the drag starts without waiting for any round trip; at most 3 per `touchmove`, the excess dropped; finger down = wheel up; the reported cell is the one under the finger, encoded in the program's protocol; how far one wheel step scrolls is up to the program (for a program with step N, dragging k rows moves the content about k × N lines); `touchmove` is `preventDefault`ed while converting; horizontal drags and taps send no wheel events. Without mouse tracking nothing changes: the main screen uses xterm's touch scrolling, and the alternate screen doesn't move and sends no arrow keys | UT-touch-1, E2E-44 |
| AC-3.22 | **The text page follows the session** ([ADR-0036](../20-architecture/adr/0036-text-page-per-session.md)): each session remembers which page it's on (keys / text) and its draft; switching sessions swaps the extra-keys slot to the new session's page and the text box to the new session's draft, and switching back restores both; new sessions start on the keys page with an empty draft; the draft is discarded when the session closes; Enter sends only to the current session and clears only its draft; switching mid-composition commits the composition before saving the draft | UT-textinput-2, E2E-40 |
| AC-3.23 | **Sending files** ([ADR-0051](../20-architecture/adr/0051-send-files-to-a-session.md)): the text page has a paperclip `text-upload-file` over the text box's bottom-right corner (its icon inside the box; the box as wide as the slot minus the left column and the 6px gaps, still bordered and fully inside it; tapping it keeps focus where it was; no `resize`), and the `wide` tab bar has `upload-file` between the spacer and `conn-dot`; both open one hidden `<input type="file" multiple>` (`upload-input`, no `accept`). Pasting a clipboard with files and an empty `text/plain` into the terminal or the text box, or dropping files anywhere on the page while the file browser is closed (AC-9.8), does the same; a paste with text is a normal text paste; a dropped file never replaces the page.
