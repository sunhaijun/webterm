# 设备与布局矩阵

> 状态：Accepted

定义支持范围和各档的目标体验。布局实现细节见 [`../40-frontend/layout-responsive.md`](../40-frontend/layout-responsive.md)。

---

## 目标设备优先级

webterm 的差异化价值集中在移动端 —— 桌面上你本来就有本地终端可用。所以优先级是：

1. **手机（竖屏）** — 最高优先级。通勤、临时排障。最难做好，也最有价值。
2. **平板** — 次高。有一定屏幕面积，可能配外接键盘。
3. **桌面** — 必须完整可用，但不是差异化重点。
4. **手机（横屏）** — 需要能用（看宽输出、看日志），但不优化输入。

## 断点

| 断点 | 宽度 | 形态 |
|---|---|---|
| `phone` | `< 640px` | 全屏终端 + 底部功能键条 + Composer；会话切换用底部 sheet / 左右滑动 |
| `tablet` | `640px – 1023px` | 单栏终端 + 底部浮层式会话列表（ADR-0018） |
| `desktop` | `≥ 1024px` | 常驻侧栏（会话列表）+ 终端 + Composer |

断点只依据视口**宽度**，不做 UA 嗅探。触摸能力用 `@media (pointer: coarse)` 单独判断（决定是否显示功能键条、命中区域尺寸）。

## 各档目标

### phone（`< 640px`）

- **终端占据除功能键条和 Composer 外的全部高度**，没有标题栏浪费空间（会话名和状态挤在一条 28px 的细条里）
- 软键盘弹出用 `visualViewport` 处理，终端区收缩而非被遮挡；功能键条始终贴在键盘上方
- 默认字号偏大（保证可读），列数因此较少（约 40–50 列）；这是刻意的取舍：**可读 > 兼容宽输出**
- 会话切换：底部上拉 sheet，卡片式（每张卡片带最后几行输出预览 + 未读标记）；也支持在终端区左右滑动切换
- 快捷命令：Composer 上方一排可横滑的按钮
- 尊重 `env(safe-area-inset-*)`（刘海、Home 指示条）

### tablet（`640–1023px`）

- 会话列表是贴底的浮层（ADR-0018），点状态条或 ⋯ 打开，打开时终端不重排（`fixed` 覆盖式）
- 默认字号中等，约 80 列
- 有外接键盘时（`pointer: fine` 且无 `coarse`）隐藏功能键条，启用桌面快捷键

### desktop（`≥ 1024px`）

- 侧栏常驻，默认宽 240px；**右缘可拖改宽**（200–480px，上限再受窗口宽 40% 约束）——
  拖动中分隔条跟手画出落点，**松手才落宽度**（拖动期间不重排终端，ADR-0021）；
  点分隔条或 `Ctrl+Shift+B` 收起 / 展开，收起后终端满屏、左缘留一条拉出把手。
  宽度与收起状态持久化到 `localStorage`
- 完整快捷键
- 默认 80+ 列，字号可自由调
- Composer 与 Raw 模式的切换有明显视觉指示（Composer 有边框高亮的输入框，Raw 时输入框收起为一条提示带）

### phone landscape（`< 640px` 高度受限）

高度 `< 480px` 时额外规则：

- 功能键条折叠为单行、更矮（32px）
- Composer 收起为单行，展开时覆盖终端而不是挤压
- 会话细条隐藏，状态信息只用一个 8px 的圆点表示

## 浏览器支持

| 浏览器 | 最低版本 | 说明 |
|---|---|---|
| Chrome / Edge | 最近 2 个大版本 | 主要开发目标 |
| Safari (iOS) | iOS 16+ | 移动端主要目标；注意 `visualViewport` 和 100vh 行为差异 |
| Safari (macOS) | 16+ | |
| Firefox | 最近 2 个大版本 | |

明确不支持：IE、旧版 Android WebView（< Chrome 100）。

依赖的现代 API（不做 polyfill）：`visualViewport`、`ResizeObserver`、`CSS env()`、`WebGL2`、Clipboard API、Service Worker。

---

## PWA

- `display: standalone`，无地址栏
- 图标、主题色随系统深浅色切换
- Service Worker **只缓存静态壳**（HTML/JS/CSS/字体），不缓存任何终端数据
- 离线时展示"无法连接到 agent"的明确状态，不假装能用

## 字体

- 等宽字体栈优先用系统内置，不打包 webfont（体积 + 首屏）
- 必须包含中文等宽回退，保证 CJK 宽字符对齐
- 启用 xterm 的 `unicode11` addon 以正确计算 CJK 与 emoji 宽度
